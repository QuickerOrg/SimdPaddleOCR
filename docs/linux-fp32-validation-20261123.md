## 结果

- Linux RTX4080 SUPER上，四模式CLI96图/509行、HTTP开启小图优化后96图/545块均完成。FP32候选与修复后的CPU概率末端文字、CTC及字符边界一致；最大字符分数差0.00078347、块分数差0.00021770。原GPU的英文切分差由候选修复。
- 单实例确认：CPU概率末端89.41次/秒、186.63 CPU ms/次；GPU FP32候选88.90次/秒、100.28 CPU ms/次。三轮吞吐比约−0.54%，近似区间包含0，CPU成本约减少46%。没有复现Windows的稳定吞吐优势。
- 三个测试实例同时常驻的六轮实验为96.85/88.16/89.43次/秒（CPU/原GPU/候选），存在额外内存驻留混杂，保留而不与单实例组混算。两组共24738个计量请求均成功，无推理回退。
- 短时语音共存18次均成功，但TTS中位延迟样本从63.5ms上升到125.1ms；三样本不是SLA。

## 标准构建仍不能直接部署双GPU服务器

本轮发现原内嵌引擎VkBackend构造函数固定VkDevice.Create()，未读取旧SIMDONNX_VK_DEVICE_INDEX；同时缺少既有memfix在host-visible/device-local分配失败后尝试coherent系统内存的重试。初次未修复测试分别被选卡核验拒绝、以及出现Vulkan分配失败后隔离进程SIGSEGV。

两项修正只应用于运维的T盘隔离引擎副本，通过SimdOnnxRoot覆盖构建。**本仓没有修改子模块gitlink，不能把本次Linux通过理解为未经补丁的标准包已可部署。** 补丁及精确来源/散列保存在运维仓库`ubuntu-server-20261123/linux-fp32`，F盘包含可复现兼容源码。

HTTP仍使用旧跨平台验证封装和ModelProvider1.0.1，仅做内嵌引擎反射核验适配与OCR DLL替换，不代表正式服务项目依赖已迁移。本轮新增的CLI Linux native-assets条件和模型加载前的显卡名称核验，不改变产品默认开关。

## 后续方向

实测32GiB卡上的CPU可见/coherent设备本地堆只有246MiB，空闲预算约23MiB。当前引擎存在该类型就启用CoherentDeviceLocal，常量也优先分配其中；应用层重试并不保证常量仍留显存。本轮内核新增17条映射内存NV_ERR_NO_MEMORY断言，没有观察到Xid或正式服务重启，仍不能作为长期稳定性通过。

建议先核对常量实际驻留、独立暂存上传以及提交/等待，消除这种小堆耗尽路径，再看NUMA/并发与GPU内核。不继续根据桌面结果直接推广GPU末端。正式四服务PID、重启次数和OCR DLL散列与测试前一致，测试进程/端口均已关闭。
