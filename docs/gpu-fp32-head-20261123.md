# GPU末端FP32 logits输出原型

2026年11月23日。基点2c9114c，固定引擎cb80be7370f280c4ca62f1679c71f05688a66001。仅本机Windows离线实验，没有访问Linux、启动HTTP、替换现有服务或改变默认行为。

## 结果与建议

FP32输出恢复了英文文章空格的[92,94) CTC run，消除了相对CPU的2.66585px字符边界差。96图509行中，文字、CTC起止和字符边界与CPU末端一致。最大字符分数差由原GPU的0.49715632降至0.00078347，最大行分数差由0.00649746降至0.00021770；仍不是逐位分数兼容。

本机固定8个P核、4并发整图API，4个10秒窗口/模式，FP32候选平均141.52图/秒，原GPU145.44，CPU末端74.85。配对吞吐相对原GPU下降2.71%，每请求CPU约27.57ms，相对CPU末端92.23ms下降70.12%。本次固定CPU集合及选项与旧HTTP测试不同，不能把相对CPU的89%吞吐提升视为Linux预期或与旧27%直接比较。

batch16/宽320的单图arena由47.1084MiB增至70.0708MiB，投影＋归约GPU时间约0.243ms→0.275ms。建议保留候选，下一步才进入Linux独立实例验收；不直接部署。

## 实现

`Experimental/GpuFp32Head.cs`注册Physical graph pass，把末端GEMM与Softmax替换为两个扩展dispatch：原通用GEMM输出到FP32 scratch，再从FP32 logits做稳定分母归约，输出已有的6字节compact格式。主干、FP16激活/权重、FP32 bias、GEMM累加算法和最小索引平局规则不变。

仅接受Small K=120、C=18710的普通非转置、无激活投影。该维度在原后端也走通用GEMM，避免同时改变tensor-core算法。通过同一逻辑Buf追踪reshape别名，确认logits只有Softmax一个读者；不按可能重用的arena偏移猜生产者。不改引擎子模块或公共API，不给整个网络开FP32。

`ctc_projection.comp`复制固定引擎通用gemm，仅以LOGITS_FP32控制输出类型；FP16对照和FP32候选用相同glslang编译。`ctc_reduce32.comp`复制原compact归约，仅把输入类型改为float，输出字节仍按主图存储精度写回。

需要同时设置两个实验环境变量，并在创建实例前设置：

```text
SIMD_OCR_EXPERIMENT_COMPACT_HEAD=1
SIMD_OCR_EXPERIMENT_COMPACT_KERNEL=fp32
```

`fp16-control`使用同样的扩展pass与新GEMM源码，但输出FP16 scratch；96图的完整结果及字符框与原GPU逐字段相等，排除了当前样本上的编译/图改写混杂。开关默认关闭。GPU图按实例缓存，不支持任意切换环境变量后把旧实例当新模式；质量测试每模式独立进程，性能测试用各自实例并在相应模式下预热和运行。

## 验证及限制

- 合成回归复现21.327156 / 21.331380在FP16中同为21.328125：原GPU与FP16对照选blank，FP32选空格；覆盖直接连接和Unsqueeze别名两种图。
- 96张常规Small检测路径，60图检出509行。36图无框，未模拟服务小图单行/补边路径，不表示线上识别失败。各模式每图两次，均稳定，无GPU回退，分数有限且在[0,1]。
- CPU与FP32候选的行分数0.5/0.8阈值、对齐token分数0.5/0.8阈值均无穿越；当前样本不代表所有阈值或所有数据。未批准放宽分数契约。
- 英文空格CPU分数0.50105435，FP32候选0.5009017；未消除权重FP16量化和GPU/CPU矩阵乘、分母浮点顺序差异，不能把剩余误差全部归因于softmax。
- 初次真实模型匹配遗漏reshape别名，触发回退，被GPU状态断言拒绝；修正后96图重跑通过。没有把回退结果计入候选。
- 全库105通过、1个既有设计跳过；netstandard2.0构建成功，保留子模块已有CS0108警告。

## 复现

```powershell
./test/Sdcb.SimdPaddleOCR.GpuExperiments/build-fp32-shaders.ps1 -Compiler <glslang.exe>
dotnet build test/Sdcb.SimdPaddleOCR.GpuExperiments/Sdcb.SimdPaddleOCR.GpuExperiments.csproj -c Release --artifacts-path <隔离输出目录>
```

CLI入口：

```text
--fp32-quality <模型目录> <图片清单.json> <输出目录> <cpu|baseline|fp16-control|fp32>
--fp32-bench <模型目录> <四张基准图片目录> <输出.json>
--gpu-profile <模型目录> <输出.json>
```

GPU profiling另设`SIMD_OCR_GPU_PROFILE_FP32=1`；倒序另设`SIMD_OCR_EXPERIMENT_GPU_PROFILE_REVERSE=1`。CPU模式指GPU主干＋CPU概率末端，非全CPU识别。完整方法、逐轮数据和SHA见运维仓库`ubuntu-server-20261123/gpu-fp32`；模型、可执行包和完整原始质量响应另存F盘。
